# Step 4 方法

## 目标 Hive schema

每个字段记录：目标字段、Hive 类型、中文注释、业务含义、来源 mapping ID、转换 decision ID、空值、默认值、单位、敏感级别、是否分区/键、历史回填和测试 ID。字段类型必须考虑精度、时区、金额、小数、复杂类型与兼容性。

## 转换与 Join

按输入裁剪、过滤、标准化、去重、Join、派生、聚合、输出排序。每条 Join 记录左右表、键、期望基数、有效期、SCD 规则、未匹配策略、fanout 检查和失败动作。禁止用 `DISTINCT` 代替基数设计。

## 分区与增量

明确分区字段、格式、业务时间与处理时间的关系、读取窗口、水位、迟到容忍、重跑覆盖、撤销/删除、动态分区和幂等键。Hive 分区设计兼顾裁剪、文件数量、回填和消费者查询，不以“每天分区”作为无依据默认。

## 调度与回填

列出上游任务和分区 ready 条件、频率、最晚完成时间、超时、重试和 owner。回填定义时间范围、批次、并发、资源、断点、数据冻结、对账、消费者切换和终止条件。

## 质量与测试

至少覆盖 schema、主键/唯一性、核心非空、枚举、范围、引用完整性、分区新鲜度、行数/分布漂移、Join fanout、SCD 重叠、指标对账和业务验收。阈值必须来自规范、历史基线或用户确认。

## 发布与回滚

优先采用上游加性变更 → 中间层传播 → 目标双跑 → 对账 → 消费者切换 → 观察期。定义 schema 回滚、任务回滚、数据分区回滚、消费者回退和停止条件。
